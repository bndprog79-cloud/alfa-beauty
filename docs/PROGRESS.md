## Заметки
(сюда записывать важные решения и найденные проблемы)
- Номер телефона/WhatsApp в docs/data.js (77010000000) — тестовый: кнопки WhatsApp откроют приложение, но такой номер не найдётся. Перед сдачей заменить на настоящий.
- Поиск, статус работы («Открыто до…») и noscript в каркас не входят — это этапы 6 и 7.
- Кнопка «‹ …» внутри прайса делает history.back(), если предыдущий экран — её родитель; иначе (например, открыли прямую ссылку на услугу) обычный переход, чтобы не выйти из прайса.
- Этап 1, проверка на телефоне (2026-10-03): Android 10, Chrome, ссылка открыта из WhatsApp — всё работает: текст WhatsApp без искажений (кириллица, казахские буквы, «», /, ₸), кнопка на тестовый номер открывает WhatsApp, «Позвонить» открывает звонилку, навигация вперёд и системная кнопка «Назад» работают правильно, прямая ссылка #/s/test/item открывает экран 3. iPhone (Safari) и открытие из Telegram пока не проверялись — проверить на каркасе.
- Этап 3, шрифт: проверку на казахские буквы прошли оба кандидата (Cormorant Garamond и Lora); выбран Cormorant Garamond, ₸ в нём есть. По умолчанию у него старинные цифры — для цен и заголовков включены lining-nums (+ tabular-nums для цен). Скрипт шрифта на Python (fonttools + brotli), как в ТЗ.
- Этап 3, кнопка записи: сделана position: fixed и вынесена из анимируемого контейнера экрана (иначе transform во время перехода сдвигает её); после анимации класс с transform снимается. Проверено: кнопка внизу окна во время и после перехода вперёд и «Назад».
- Этап 3, контраст: пилюля «Хит» цветом --accent-strong на --surface-2 давала 4.38 (nude) и 4.40 (sage) — ниже AA. Добавлена переменная --hit-text (чуть темнее акцента: nude #8E5257, sage #526A4F, noir = --accent-strong). Остальные пары во всех темах ≥ 4.5.
- Монограмма «AB» в шапке — с этапа 4 это ILLUSTRATIONS.logo (контуры букв, не текст — пригодится для PNG-иконок на этапе 7). У логотипа квадратный viewBox 0 0 120 120 — единственное исключение из 200×140.
- Этап 4, правила цветного стиля «Яркий» (обязательны для этапа 5, подробно — tools/illustrations/README.md):
  - Палитра — только переменные --ill-* в каждой теме index.html: --ill-bg (подложка), --ill-hair-dark / -mid / -light, --ill-skin, --ill-berry (главный яркий акцент), --ill-gold, --ill-metal, --ill-line (контур), --ill-k. Новый цвет = новая переменная во всех трёх темах + класс в CSS; в рисунках только классы (c-bg, c-hd, c-hm, c-hl, c-sk, c-be, c-go, c-mt; линии lc, lh, lo), цвета только через var(--...).
  - Толщина линий: контур = 1.6 × --ill-k (0.6), т. е. тонкий; в крупном размере --sw 1.3, в мини --sw 3.4 (задано в CSS, в рисунках не трогать).
  - Подложка: у каждого рисунка общий круг BG (центр 100,70, r 46, --ill-bg). Рисунок в зоне x 44–156, y 16–124; единый визуальный вес — один главный предмет + одна деталь/инструмент + 2 золотые искорки.
  - Мини 48px: в квадрате видна только середина x 30–170, поэтому важное держать в центре; проверять читаемость в галерее.
  - Без id, градиентов, масок, clipPath (повтор id ломает Safari). Плавные переходы — стопкой полупрозрачных полос; каждая обводка — path с pathLength="1" (функция P).
  - Люди — силуэт одной тонкой линией, кожа --ill-skin, без детальных глаз, носа, губ.
  - В noir контур светлый — мелкие тёмные детали делать заливкой.
- Этап 4, размер: рисунки 12 штук ≈ 55 КБ. При таком же весе на этапе 5 index.html выйдет ≈ 260 КБ (цель 300) — рисовать экономно (меньше полос в переходах).
- Плитки категорий этапа 5 до перерисовки показывают старую бледную заглушку ILL_PLACEHOLDER — после этапа 5 её можно оставить как запасную.
- Тень и подсветка нажатия заданы переменными --shadow и --press в каждой теме.
- Этап 5, стопы — решение владельца: вместо SVG готовое изображение assets/feet-gel.png (сделано нейросетью, права на использование есть). Пока одна картинка на все четыре ключа feet-base / feet-classic / feet-gel / feet-coat; позже владелец положит отдельные assets/feet-base.png, feet-classic.png, feet-coat.png — они подхватятся автоматически при сборке (объект RASTER в tools/illustrations/build-illustrations.js). Для новых файлов кадр нужно подстроить (RASTER_FILES: crop, pos, focus, zoom).
- Растровые иллюстрации: скрипт сборки переводит PNG в WebP через ffmpeg (ширина до 480 px, качество 80, цель ≤ 40 КБ) и встраивает в index.html как data:image/webp;base64 — работает и по file://. Одинаковая картинка встраивается один раз (ILL_IMG). У feet-gel.png обрезаются огрехи исходника (светлые пятна в верхних углах и тонкая белая рамка справа и снизу); в 48px кадр приближен к ногтям. В карточке услуги вместо прорисовки — мягкое проявление, при reduced motion — сразу. Картинка не перекрашивается при смене темы (это фото).
- Векторная копия стоп (последний вариант до перехода на картинку) — tools/illustrations/backup/feet-vector.js; в продукт не входит, как вернуть — в шапке файла.
- Образцы поз от владельца tools/preview/ref-hand.png и ref-foot.png — только для справки, в .gitignore.
- Новые цвета палитры иллюстраций (во всех трёх темах, классы в CSS): --ill-aqua / c-aq — мятный (пастельные ногти); --ill-ink / c-ik — ресницы и подводка (в noir светлый, иначе не видно на тёмном фоне); --ill-brow / c-br — тёплый коричневый для бровей.
- Этап 6, часовой пояс: с марта 2024 Казахстан живёт по UTC+5. В очень старых браузерах база поясов может считать Алматы UTC+6 — тогда статус ошибётся на час. Для другого салона — поменять company.timezone (или убрать поле, тогда статус по времени телефона).
- Этап 6, поиск: по названию категории находятся все её услуги («ресниц» показывает и услуги для бровей — они в категории «Брови и ресницы»). Текст запроса хранится только в памяти страницы (не в localStorage), после перезапуска поле пустое.
- Этап 7, service worker — решение владельца (отступление от п. 9 ТЗ, где был stale-while-revalidate): страница грузится «сначала из сети» (запрос с cache: 'no-cache', таймаут 3 с), иначе из кэша — чтобы после изменения цен клиент с интернетом сразу видел новые цены. Manifest и иконки — из кэша.
- Этап 7, порядок публикации после любого изменения index.html (цены, тексты, тема): node tools/pwa/build-pwa.js → коммит → push. Скрипт меняет CACHE_VERSION в sw.js. Если забыть — новые цены всё равно видны (страница берётся из сети), но иконки/manifest не обновятся. QR пересобирать только при смене адреса сайта: node tools/qr/build-qr.js (первый раз: cd tools; npm install).
- Этап 7, manifest и значок вкладки подключаются из JS только на http/https: при открытии файлом браузер пишет ошибку CORS в консоль. apple-touch-icon — обычной ссылкой в head (её читает только Safari при «На экран Домой»).
- Этап 7, тема: build-pwa.js ставит data-theme и theme-color в <html>/<head> из meta.theme — чтобы и без JavaScript (noscript) страница была в своей теме. При смене темы — перезапустить скрипт (пересоберутся и иконки, и цвета manifest).
- Этап 7, проверка владельцем на телефоне (2026-10-04): Android — всё работает: иконка «AB» на главном экране, прайс открывается в режиме «в самолёте», QR-код сканируется. iPhone (Safari: «На экран Домой», режим «в самолёте») пока не проверялся — проверить на этапе 8.
- Этап 8, sw.js: стратегия страницы — «сначала сеть с таймаутом 3 с» (cache: 'no-cache' — браузер перепроверяет файл у сервера, GitHub Pages отвечает 304 или новую версию). При нормальной сети новая цена видна с первого открытия; если сеть отвечает дольше 3 с — показывается сохранённая копия, а новая цена появится при следующем открытии (кэш обновляется в фоне). Без сети по ссылкам с хвостом ?fbclid=… открывается из кэша (caches.match с ignoreSearch: true + запасной вариант './').
- Этап 8, неразрывный пробел: в коде index.html он записан как ' ' — так его не испортит редактор. Если появятся новые места с неразрывным пробелом — тоже писать кодом.
- Этап 5, размер: index.html ~308 КБ (SVG-рисунки ~186 КБ, картинка стоп ~11 КБ в base64); ресницы и брови из сотен штрихов — самые «тяжёлые» рисунки. Галерея по умолчанию показывает все группы: node tools/preview/build-gallery.js.
